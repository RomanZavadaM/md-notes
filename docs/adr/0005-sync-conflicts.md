# ADR-0005: Конфлікти синхронізації як окремі файли

- Статус: прийнято
- Дата: 2026-10-01

## Контекст

Local-first означає, що один файл може змінитися на двох пристроях між
синхронізаціями. Обов'язкова вимога: конфлікт ніколи не перезаписується
мовчки.

## Рішення

1. Для кожного файлу зберігається стан останньої синхронізації: хеш вмісту,
   а також ETag або ревізія віддаленого сховища.
2. Якщо змінилася лише одна сторона, зміна переноситься.
3. Якщо змінилися обидві, а вміст текстовий, застосунок пробує
   **тристороннє злиття** з базовою версією. Зливаються лише зміни, що не
   перетинаються.
4. Якщо злиття неможливе, локальна версія лишається на місці, а віддалена
   зберігається поруч як
   `Нотатка (конфлікт 2026-10-01 14-30, Pixel 8).md`.
   Конфлікт позначається в інтерфейсі: значок у дереві, список конфліктів,
   порівняння двох версій.
5. Для Git-сховищ використовується звичайний `merge`. Конфліктні файли
   отримують ту саму обробку, що й у п. 4, а не маркери `<<<<<<<`.
6. Видалення проти зміни: зміна перемагає, і файл відновлюється.

## Наслідки

- Дані не втрачаються, навіть якщо користувач ігнорує конфлікти.
- Конфліктні копії видно в будь-якому іншому редакторі.
- Для злиття потрібна база: остання синхронізована версія файлу
  зберігається в `.mdnotes/cache/`.

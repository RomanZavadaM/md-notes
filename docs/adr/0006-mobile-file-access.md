# ADR-0006: Доступ до файлів на Android та iOS

- Статус: прийнято
- Дата: 2026-10-01

> **Стан на stable v1.0.0:** Android/iOS проходять build smoke, але physical-device runtime ще не прийнятий. SAF/security-scoped external folders і WebDAV не входять до stable 1.0. Рішення нижче зберігає архітектурний напрямок, а не обіцянку релізу v0.3.

## Контекст

На настільних ОС сховище — це звичайний шлях. На мобільних платформах інакше:

- **Android**: папки поза пісочницею застосунку доступні через Storage
  Access Framework (SAF). Шляхи мають вигляд `content://…`, а не
  `/storage/…`. Права треба зберігати через `takePersistableUriPermission`.
- **iOS**: папка з «Файлів» або iCloud Drive доступна через
  security-scoped bookmarks. Доступ треба відновлювати після кожного запуску.

Стандартний `std::fs` у ядрі не працює з `content://` URI.

## Рішення

- Ядро працює зі сховищем лише через трейт `StorageProvider`
  ([ADR-0003](0003-storage-providers.md)).
- **Режим за замовчуванням на мобільних**: сховище живе в пісочниці
  застосунку (звичайний `std::fs`) і синхронізується з Git, WebDAV або
  хмарою. Це надійно і швидко.
- **Додатковий режим**: зовнішня папка через окремий Tauri-плагін з
  реалізаціями `SafProvider` (Kotlin) і `BookmarkProvider` (Swift). Індекс
  при цьому лишається в пісочниці.
- Тому базова синхронізація (Git, WebDAV) виходить разом з мобільною
  версією у v0.3.

## Наслідки

- Мобільна версія корисна з першого релізу: нотатки синхронізуються з
  комп'ютером.
- Режим зовнішньої папки вимагає нативного коду на Kotlin і Swift і
  ретельного тестування на реальних пристроях.

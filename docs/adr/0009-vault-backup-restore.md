# ADR-0009 — резервне копіювання та відновлення сховища

**Статус:** запропоновано, 27.10.2026. **Не реалізовано.** Цей документ визначає безпечні межі першого етапу; зміна статусу потребує реалізації та тестів.

## Контекст

MD Notes — local-first застосунок зі звичайними і зашифрованими (age) сховищами, вкладеннями й службовою конфігурацією. Власник просить можливість відновити дані після збою чи перенесення. Потрібно уникнути мовчазного перезапису й випадкового відкриття приватного вмісту.

## Запропоноване рішення (перший зріз)

1. Команди «Створити резервну копію…» та «Відновити резервну копію…» — окремі явні дії користувача. Жодної автоматичної копії чи upload без окремого рішення. Каталог призначення вибирає користувач.
2. Формат: переносимий ZIP із `manifest.json` (версія формату, версія програми, час створення, режим шифрування, перелік шляхів, розмірів і SHA-256) та файлами сховища з **відносними** шляхами. Шляхи в архіві нормалізувати, заборонити `../`, абсолютні шляхи, symlink traversal, дублікати/колізії регістру. Маніфест не включає приватні ключі чи токени.
3. Для encrypted vault у backup потрапляють тільки дані в зашифрованому вигляді; не використовувати `readNote` для експорту plaintext. Попереджати, що потрібна окремо збережена recovery key; ніколи не додавати її до ZIP автоматично. Не класти системне сховище секретів у backup.
4. Кеш індексу, тимчасові файли, OS-specific state і git credentials не включати. Включати вміст сховища, зокрема приховану службову конфігурацію, потрібну для відкриття, та вкладення. Правила для `.git` і синхронізації затвердити до реалізації; за замовчуванням не включати git credentials і не робити неочевидного перенесення remote identity.
5. На час створення backup забезпечити консистентність: завершити/явно підтвердити незбережені редакторські зміни; зафіксувати список/метадані джерел, виявляти зміни файлів під час читання, при гонці — завершувати з помилкою, не видавати частковий архів за готовий. Писати у тимчасовий файл і атомарно перейменовувати тільки після успіху.
6. Restore: перевірка маніфесту та SHA-256 **перед** змінами в цільовій папці; розпакування в новий тимчасовий каталог, перевірка коректності, фінальне атомарне перейменування в **нове** сховище. Не перезаписувати наявне сховище. Показати зведення перед відновленням.
7. Помилки: пошкоджений архів, відсутній ключ, неприпустимі шляхи, замало місця, переривання операції, зміна вихідних файлів, ZIP-bomb/обмеження ресурсів — з безпечною відмовою й очищенням тимчасових артефактів.

## Критерії приймання

- Round-trip звичайного сховища: нотатки, вкладення, налаштування, вкладені папки, Unicode.
- Round-trip encrypted vault: на диску в ZIP немає plaintext; з окремим ключем відновлене сховище відкривається; без ключа — пояснення, а не незахищений обхід.
- Тести corruption/checksum mismatch, path traversal, колізій, incomplete backup, змін під час архівації і відновлення в зайнятий каталог.
- Жодного мережевого запиту, автоімпорту чи перезапису за замовчуванням.
- UI та довідка сімома мовами, CI за політикою path-aware, runtime acceptance Windows перед релізом.

## Відкладено

Автоматичний розклад, ротація/історія копій, зовнішнє хмарне сховище, інкрементальні копії, злиття backup із чинним vault. Спочатку потрібні ручний backup та перевірене restore.

# ADR-0003: Провайдери сховищ

- Статус: прийнято
- Дата: 2026-10-01

## Контекст

Потрібні локальна папка, WebDAV, SFTP, SMB, Google Drive, OneDrive, Dropbox,
S3-сумісні сховища і Git. Початковий план покладався на OpenDAL для всіх
варіантів. Перевірка показала обмеження:

- **SMB** — у OpenDAL немає готового сервісу.
- **SFTP** — сервіс OpenDAL використовує системний OpenSSH, тож працює лише
  на Unix-подібних системах. На Windows, Android та iOS він недоступний.
- **Git** — це не файлове сховище, а історія версій. Його модель (коміти,
  гілки, злиття) не вкладається в API «прочитати/записати файл».

Ці висновки треба перепідтвердити з актуальною документацією OpenDAL перед
реалізацією v0.3–v0.4.

## Рішення

Ядро визначає власний трейт `StorageProvider` (список, читання, запис,
видалення, метадані, зміни з певного моменту). Реалізації:

| Сховище | Реалізація | Етап |
|---|---|---|
| Локальна папка | `std::fs` | v0.1 |
| Git (GitHub, GitLab) | `gix` (gitoxide) з HTTPS і токеном | v0.3 |
| WebDAV | OpenDAL | v0.3 |
| S3-сумісні | OpenDAL | v0.4 |
| SFTP | `russh` + `russh-sftp` (чистий Rust, усі платформи) | v0.4 |
| Google Drive, OneDrive, Dropbox | OpenDAL + OAuth через системний браузер | v0.5 |
| SMB | системне монтування; бібліотека — після дослідження | v0.6 |

Усі віддалені сховища працюють як local-first: локальна копія і фонова
синхронізація ([ADR-0005](0005-sync-conflicts.md)).

## Наслідки

- Набір провайдерів не залежить від можливостей однієї бібліотеки.
- Git-сховище отримує справжню історію версій, а не лише копію файлів.
- Підтримка кількох бібліотек коштує більше, ніж одна OpenDAL.

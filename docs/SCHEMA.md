# Типи нотаток і `.mdnotes/schema.json`

MD Notes не переносить властивості нотаток у власну базу даних. Джерелом істини лишається Markdown-файл, а властивості зберігаються у звичайному YAML front matter. Файл `.mdnotes/schema.json` лише описує, які поля зручно показувати у формі для певного `type`.

## Принцип сумісності

Формат v1 — це формат, який уже використовується у `sample-vault/.mdnotes/schema.json`:

- `fields` — глобальний каталог полів;
- `types` — типи нотаток;
- `types.<name>.fields` — поля, які показуються для типу;
- `types.<name>.required` — обов'язкові поля;
- `type:` у YAML front matter вибирає тип нотатки.

Невідомі YAML-поля не видаляються. Невідомий `type` не робить нотатку недоступною. Якщо front matter має синтаксичну помилку, форма відмовляється його переписувати, доки YAML не буде виправлено вручну.

## Приклад

```json
{
  "version": 1,
  "fields": {
    "status": {
      "type": "enum",
      "label": "Статус",
      "values": ["todo", "doing", "done"]
    },
    "due": { "type": "date", "label": "Термін" },
    "tags": { "type": "list", "label": "Теги" },
    "id": { "type": "text", "label": "Ідентифікатор", "readonly": true }
  },
  "types": {
    "task": {
      "label": "Задача",
      "template": "task.md",
      "fields": ["status", "due", "tags"],
      "required": ["status"]
    }
  }
}
```

Нотатка залишається звичайним Markdown:

```markdown
---
type: task
status: doing
due: 2026-10-15
tags: [робота, важливе]
custom_field: це поле схема не забирає
---

# Приклад задачі
```

## Типи полів v1

- `text`, `string` — текст;
- `number` — число;
- `boolean` — прапорець;
- `date` — дата;
- `enum` — вибір одного значення з `values`;
- `list` — список рядків;
- `link` — одне текстове посилання на нотатку;
- `links` — список посилань;
- `url` — URL;
- `file` — шлях/посилання на файл.

Додаткове поле `noteType` у `link` / `links` може описувати очікуваний тип цільової нотатки. У v0.2 форма зберігає його як частину відкритої схеми; фільтр вибору пов'язаних нотаток можна розвивати окремо.

`readonly: true` робить поле лише для читання у формі. Значення при цьому залишається звичайним YAML і може бути відредаговане вручну у Markdown.

## Як працює форма

Кнопка **«Властивості»** знаходиться у редакторі. Форма читає поточний текст CodeMirror, а не останню копію з диска. Після натискання **«Застосувати»** ядро формує новий текст front matter у пам'яті та повертає його редактору. Далі спрацьовує звичайний механізм autosave.

Це важливо: незбережені зміни у тілі нотатки не перезаписуються окремою операцією форми.

## Межі v0.2

- форма редагує лише верхньорівневі властивості, описані для вибраного типу;
- довільні невідомі поля зберігаються;
- застосування форми може нормалізувати форматування YAML front matter (відступи, стиль списків, порядок серіалізації); значення полів і тіло Markdown зберігаються, але коментарі всередині YAML не гарантуються;
- редагування самого `schema.json` поки виконується як звичайного JSON-файлу поза окремим GUI-редактором схеми.

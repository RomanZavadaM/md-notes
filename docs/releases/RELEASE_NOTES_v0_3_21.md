# MD Notes v0.3.21 — тестовий prerelease

Дата checkpoint: 28.10.2026.

## Головна зміна

Цей prerelease переносить MD Notes від одного основного редактора до першої повної реалізації багатовіконного редактора за ADR-0010 (M1–M3).

### M1 — вкладки та незалежні чернетки

- кілька vault-нотаток можна тримати відкритими одночасно у вкладках;
- кожна вкладка має власний стан чернетки та збереження;
- перемикання між вкладками не повинно втрачати незбережений текст;
- зовнішні `.md/.markdown` залишаються окремими документами та не імпортуються у vault автоматично.

### M2 — незалежні editor-вікна

- для активної vault-нотатки додано **«Відкрити в окремому вікні»**;
- перед перенесенням поточна чернетка зберігається;
- після успішного створення окремого вікна нотатка забирається з main-вкладок;
- головний редактор повертається до попередньої вкладки або порожнього стану з доступним деревом сховища;
- окреме вікно залишається повноцінним редактором із режимами Редактор / Поруч / Перегляд та автозбереження;
- погоджену логіку окремого вікна графа не змінено.

### M3 — захист даних між вікнами

- перед записом перевіряється, чи файл на диску не змінився після його відкриття;
- при конфлікті MD Notes не робить тихий overwrite;
- dirty detached editor перехоплює системне закриття і закривається лише після успішного guarded save;
- перед перемиканням vault і перед Quit зберігаються всі відкриті вкладки, а не лише активна;
- повний Quit спочатку просить усі detached editor-вікна пройти їхній safe-close і не завершує застосунок примусово, якщо якесь вікно лишилось через помилку або конфлікт.

## Статус ручного тестування

Це **тестовий prerelease**. На момент публікації автоматичні збірки зелені, але ручний runtime acceptance нового багатовіконного UX ще не заявляється.

Для Windows Portable потрібно вручну перевірити щонайменше:

1. відкрити 2–3 vault-нотатки у вкладках;
2. змінити текст у різних вкладках і перевірити, що перемикання не губить чернетки;
3. винести активну нотатку через «Відкрити в окремому вікні»;
4. продовжити роботу з іншими нотатками в головному вікні;
5. перевірити, що повторне відкриття вже відокремленої нотатки не створює небезпечну другу редаговану копію;
6. змінити той самий файл іншим шляхом і перевірити, що conflict guard блокує тихий overwrite;
7. закрити dirty detached-вікно через системний ×;
8. виконати Quit із кількома відкритими/зміненими документами;
9. перевірити роботу окремого графа поруч із main: клік вершини змінює активну нотатку в main без примусового згортання/фокусу графа.

## Відомі межі

- ручне приймання Windows/macOS/Linux для багатовіконності ще попереду;
- Android/iOS тут мають build-smoke, а не physical-device runtime validation;
- резервне копіювання/відновлення за ADR-0009 ще не реалізовано;
- групові операції з файлами/папками, Git ↔ SyncManifest, WebDAV, encrypted-vault gaps і signing залишаються у backlog;
- збірки не вважати підписаними, доки release notes прямо не вкажуть інше.
